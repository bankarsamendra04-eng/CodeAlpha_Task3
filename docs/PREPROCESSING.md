# MAESTRO Dataset Preprocessing & Split Pipeline

## Overview

The **AI Music Studio** preprocessing pipeline transforms the complete raw [MAESTRO v3.0.0](https://magenta.tensorflow.org/datasets/maestro) MIDI dataset (1,276 virtuosic piano performances, ~198.65 hours of audio) into a compact, quantized token sequence representation suitable for training sequence models (LSTM/RNN).

---

## Key Architecture & Design Principles

```
Raw MIDI Files (1,276 files)
        │
        ▼
[File-Level Train/Val/Test Split] (80% / 10% / 10%, random_seed=42)
        ├──> `dataset/splits/train.csv` (1,020 files)
        ├──> `dataset/splits/validation.csv` (128 files)
        ├──> `dataset/splits/test.csv` (128 files)
        └──> `dataset/splits/split_summary.json`
        │
        ▼
[Parallel Token Extraction] (music21 MIDI event streaming, multi-process)
        │
        ▼
Per-File Token Cache (`dataset/processed/token_cache/*.json`)
        │
        ▼
[Vocabulary Construction & Pruning] (Built strictly on TRAIN split, min_freq=5)
        │
        ├──> `dataset/processed/vocabulary.json` (36,700 unique tokens)
        │
        ▼
[Sliding-Window Sequence Generator] (seq_len=50, split-isolated streaming)
        │
        ▼
[Chunked Storage (.npz)] (uint16 arrays, 50,000 samples/chunk)
        ├──> `dataset/processed/training_data/train/chunk_0001.npz` ... (73 chunks, 3,629,619 sequences)
        ├──> `dataset/processed/training_data/validation/chunk_0001.npz` ... (9 chunks, 444,333 sequences)
        └──> `dataset/processed/training_data/test/chunk_0001.npz` ... (9 chunks, 443,046 sequences)
        │
        ▼
[Preprocessing Report & Metadata]
        └──> `dataset/processed/metadata.json`
```

## 1. Reproducible Dataset Splits (80% / 10% / 10%)

### File-Level Splitting Principle
Sequences from the same musical composition must never leak across training, validation, or test sets. Therefore, the partition is executed strictly at the **MIDI-file level** prior to any sequence windowing.

### Split Metrics

| Split | Number of Files | Percentage | Duration (Hours) | Duration (Formatted) | Musical Events | Sequences Generated |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Train** | **1,020** | **79.94%** | 159.45 h | 159h 26m 55s | 40,819,202 | **3,629,619** |
| **Validation** | **128** | **10.03%** | 19.66 h | 19h 39m 44s | 4,834,676 | **444,333** |
| **Test** | **128** | **10.03%** | 19.54 h | 19h 32m 30s | 4,882,076 | **443,046** |
| **Total** | **1,276** | **100.0%** | **198.65 h** | **198h 39m 09s** | **50,535,954** | **4,516,998** |

### Split Verification & Disjointness
- **Train $\cap$ Validation**: 0 files
- **Train $\cap$ Test**: 0 files
- **Validation $\cap$ Test**: 0 files
- **Union**: Exactly 1,276 files (100% accounted for, verified by automated unit tests in `tests/test_splits.py`).
- **Reproducibility**: Governed by `RANDOM_SEED = 42`.

## 2. Tokenization & Musical Representation

### Fast Streaming MIDI Parsing
- Avoids expensive score expansion and flattening (`score.flatten()`) which takes 30–50 seconds per full concerto.
- Uses `music21.midi.MidiFile` raw track event streaming. Note-on and note-off events are matched in a single pass with ticks-per-quarter-note scaling.
- Simultaneous notes within a 0.05-quarter window are deterministically grouped into ascending chords.
- Durations are quantized to standard musical divisions ($1/32, 1/16, 1/8, 1/4, 1/2, 1, 2, 4$ quarter lengths).
- Rests longer than a sixteenth note ($0.25q$) are preserved as explicit `REST` tokens.

### Vocabulary Isolation & Pruning
- **Zero data leakage**: The vocabulary is built strictly from the 1,020 files in the **train** split.
- Reserved tokens:
  - `<PAD>`: ID 0
  - `<UNK>`: ID 1
  - `<START>`: ID 2
  - `<END>`: ID 3
- Rare tokens appearing fewer than `MIN_TOKEN_FREQUENCY` (default 5) in the training split are mapped to `<UNK>`, keeping the vocabulary at 36,700 unique tokens (down from 185,344 raw types).
- Unseen tokens encountered in validation or test streams are safely mapped to `<UNK>` (ID 1).

---

## 3. Memory-Safe Streaming & Chunking

- **Zero monolithic arrays**: The pipeline never loads all sequences into RAM at once.
- Sequences are generated by streaming through cached files one by one.
- Sliding window size is configurable (default `SEQUENCE_LENGTH = 50`).
- Whenever the in-memory sequence buffer reaches `CHUNK_SIZE = 50,000`, it is converted to a compact `uint16` NumPy array and saved as a compressed archive (`chunk_XXXX.npz`).
- Because token IDs fit in `uint16` ($\le 65,535$), each chunk requires only ~5 MB in memory and ~1.2 MB compressed on disk.

## 4. Directory Structure

```
dataset/
├── midi/                        # Symlink or source MAESTRO directory (1,276 files)
├── maestro_inventory.csv        # Comprehensive file inventory
├── maestro_analysis.csv         # Per-file musical metadata
├── dataset_summary.json         # Global statistical summary
├── splits/
│   ├── train.csv                # 1,020 training files
│   ├── validation.csv           # 128 validation files
│   ├── test.csv                 # 128 test files
│   └── split_summary.json       # Split metrics and verification
└── processed/
    ├── vocabulary.json          # Token -> integer ID mapping (36,700 tokens)
    ├── metadata.json            # Preprocessing report & metrics
    ├── token_cache/             # Per-file extracted token JSON caches (1,276 files)
    └── training_data/           # Compressed NumPy chunks (.npz)
        ├── train/               # 73 chunk files (3,629,619 sequences)
        ├── validation/          # 9 chunk files (444,333 sequences)
        └── test/                # 9 chunk files (443,046 sequences)
```
